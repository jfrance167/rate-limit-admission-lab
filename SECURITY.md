# Security model

This is an offline synthetic learning lab. It computes admission budget decisions and does not protect a service or execute application effects. Identity labels are declarations, not credentials; independent keys do not demonstrate authenticated scope or fairness. Use invented data only.

Trust the owned reviewed Python code/interpreter and frozen synthetic fixture provenance. Treat input bytes as hostile for bounded parsing, schema and report integrity. Fixed lexical gates and strict JSON hooks reject duplicate keys, float/nonfinite input, invalid Unicode and resource excess. Full event validation, including late errors and identity/time bounds, precedes any model/report. Exact integers avoid arithmetic rounding. Every policy denial still appears in the report and advances time appropriately without budget debit.

Permitted synthetic metadata is intentionally reported; no privacy/redaction guarantee. Error channels use closed codes rather than input/path/native exceptions. Exceptions in a library caller's own traceback/memory can retain data; the CLI's content-free diagnostics are not memory erasure. Report rendering completes before emission, but failed sinks can leave partial bytes and diagnostic delivery can itself fail.

Input gates bound admitted workload, not wall-clock/RSS or filesystem isolation. Regular-file checks do not defeat open-time races, symlink changes, blocking I/O or same-user compromise. No clocks/sockets/HTTP/providers/real quotas/target testing, persistence, multithreading/distributed coordination, executed effects or enforcement is provided. Extending those boundaries requires a separate scoped plan and authorization.

Verification is finite local evidence, documented in VERIFICATION.md/REVIEW.md. Six narrowly explained test/verifier subprocess scanner exceptions, no application exclusions. Prepared GitHub security checks have not run; no remote security/protection/eligibility claim. No paid services, external messaging or secret stores are part of this project.
